# AI Learning Day 1 - AI와 LLM, 프롬프트의 기초

## 1. 학습 목표

AI를 단순히 질문에 답해주는 도구로 사용하는 것을 넘어, 원하는 결과를 얻기 위해 효과적으로 활용하는 방법을 배우기 시작했다.

이번 학습에서는 다음 내용을 목표로 했다.

- AI, 머신러닝, 딥러닝, 생성형 AI의 관계 이해
- LLM의 기본적인 동작 원리 이해
- 프롬프트를 구성하는 요소 학습
- 같은 질문이라도 프롬프트에 따라 결과가 달라지는 이유 이해
- AI가 제공한 답변을 검증하는 방법 학습

## 2. AI와 LLM의 기초

### AI, 머신러닝, 딥러닝, 생성형 AI

AI는 인간의 지능적인 작업을 컴퓨터가 수행하도록 하는 넓은 분야다.

머신러닝은 데이터로부터 패턴을 학습하는 AI의 한 분야이며, 딥러닝은 여러 층의 신경망을 활용하는 머신러닝의 한 분야다.

생성형 AI는 학습한 패턴을 바탕으로 새로운 텍스트, 이미지, 코드 등의 결과물을 생성하는 AI다. 현재 널리 사용되는 생성형 AI의 상당수는 딥러닝 기술을 기반으로 한다.

이전에 참여했던 태양광 발전량 예측 프로젝트에서 사용한 XGBoost는 머신러닝 모델이며, ChatGPT와 같은 LLM 기반 생성형 AI와는 목적과 동작 방식이 다르다는 점도 다시 정리했다.

### LLM이란?

LLM(Large Language Model)은 대규모 언어 데이터를 학습한 언어 모델이다.

LLM은 입력된 문맥을 바탕으로 다음에 올 가능성이 높은 토큰을 예측하고, 이 과정을 반복하면서 문장을 생성한다.

LLM을 이해하기 위해 다음 개념도 함께 공부했다.

- **Token:** 모델이 텍스트를 처리하고 생성하는 기본 단위
- **Context:** 모델이 답변을 생성할 때 참고하는 입력 정보와 대화 내용
- **Context Window:** 모델이 한 번에 처리할 수 있는 문맥의 범위
- **Hallucination:** AI가 사실과 다르거나 근거가 부족한 내용을 그럴듯하게 생성하는 현상

AI는 그럴듯한 답변을 생성할 수 있지만, 그것이 반드시 정확한 사실이라는 의미는 아니다. 따라서 중요한 정보는 별도로 확인하고 검증하는 과정이 필요하다.

## 3. 프롬프트 구성 방법

좋은 결과를 얻기 위해 프롬프트에 포함할 수 있는 다섯 가지 요소를 공부했다.

| 요소 | 의미 |
|---|---|
| Task | AI에게 무엇을 시킬 것인가 |
| Context | 어떤 배경 정보를 제공할 것인가 |
| Constraints | 어떤 조건이나 제한을 둘 것인가 |
| Output Format | 결과를 어떤 형태로 받을 것인가 |
| Success Criteria | 어떤 결과를 좋은 결과로 판단할 것인가 |

질문을 구체적으로 작성하면 AI가 요청의 의도를 이해하고 원하는 형태로 답변하는 데 도움이 된다.

다만 프롬프트가 무조건 길다고 좋은 것은 아니다. 문제 해결에 필요한 정보를 명확하게 전달하는 것이 중요하다.

이번에는 실제 게임 개발 상황을 가정해 문제 해결을 위한 프롬프트를 작성했다.

Unity 6과 C#으로 개발하는 게임에서 플레이어가 공격할 때 공격 애니메이션이 간헐적으로 재생되지 않는 상황을 설정했다.

처음에는 Animator의 State나 Transition 설정이 잘못되었을 가능성을 생각했다.

### 5-2. 처음 작성한 프롬프트

처음에는 내가 생각한 문제 상황과 원하는 답변 방향을 중심으로 프롬프트를 작성했다.

**작성한 프롬프트**

> 난 Unity 개발자이고 현재 Unity 게임에서 플레이어가 공격할 때마다 공격 애니메이션이 재생되지 않는 버그가 발생하고 있어. AI에게 원인을 분석하고 해결방법을 요청하려고 해.
>
> Unity 6를 사용하고 있고 C# 기반이고 게임 개발 초보자가 이해할 수 있도록 설명해줘.
>
> 내가 보기에는 Unity 애니메이션 state가 잘못된 거 같아.
>
> 코드는 이런 식으로 작성되어 있고 기존 코드 구조를 최대한 유지해줘.

> 코드 ---- Unity 코드 첨부 ----
>
> 원인 후보들을 알려주고 확인 방법을 알려줘. 확실하지 않은 부분은 추측이라고 말해주도록 해.

**처음 프롬프트에서 잘한 점**

- 게임 개발 초보자라는 학습 수준을 전달했다.
- 의심하는 원인을 AI에게 알려주었다.
- 기존 코드 구조를 유지하도록 요청했다.
- 원인 후보와 확인 방법을 구분해서 요청했다.
- 확실하지 않은 내용은 추측이라고 표시하도록 했다.

### 5-3. 처음 프롬프트의 개선점

작성한 프롬프트를 다시 검토하면서 몇 가지 보완할 부분을 발견했다.

**① 특정 원인에 편향될 가능성**

내가 Animator State 문제를 의심한다고 전달하면 AI가 다른 원인보다 Animator 설정에 집중할 수 있다.

따라서 내가 생각한 원인은 하나의 가능성으로 전달하고, 다른 원인도 독립적으로 검토하도록 요청하는 것이 좋다.

**② 문제 분석과 코드 수정을 구분할 필요**

원인이 정확하게 확인되지 않은 상태에서 AI가 코드를 먼저 수정하면 실제 문제를 파악하기 어려워질 수 있다.

따라서 원인 분석과 확인을 먼저 진행하고, 그다음 해결 방법을 제시하도록 요청하는 것이 좋다.

**③ 추가 정보 요청 조건**

코드만으로 문제를 판단하기 어려울 수 있다. Animator Controller의 파라미터, Transition 조건 등 추가 정보가 필요하다면 먼저 질문하도록 요청하는 것이 좋다.

### 5-5. 개선 전후 비교 및 배운 점

| 문제 상황 | 간단하게 설명 | 문제와 예상 상황 구분 |
| 원인 분석 | 의심하는 원인 중심 | 여러 원인을 독립적으로 검토 |
| 코드 수정 | 기존 구조 유지 요청 | 원인 확인 전 임의 수정 금지 |
| 추가 정보 | 별도 조건 없음 | 부족한 정보가 있으면 먼저 질문 |
| 답변 구성 | 원인과 확인 방법 요청 | 원인, 이유, 확인, 해결 방법 구분 |

이번 실습을 통해 프롬프트를 개선한다는 것은 단순히 문장을 길게 만드는 것이 아니라, AI가 문제를 잘못 이해하거나 성급하게 결론을 내리지 않도록 요청의 구조와 조건을 보완하는 과정이라는 점을 배웠다.

특히 내가 생각한 원인을 AI에게 전달하더라도 그것이 정답이라고 가정하지 않도록 하는 것이 중요하다고 느꼈다.

## 6. 오늘 배운 핵심 개념

### Prompt Engineering

AI가 원하는 작업을 수행할 수 있도록 프롬프트를 구성하고 개선하는 방법이다.

### Context Engineering

AI가 문제를 올바르게 이해하고 답변할 수 있도록 필요한 배경 정보, 자료, 대화 문맥 등을 제공하는 방법이다.

### Verification

AI가 제공한 답변을 그대로 신뢰하지 않고, 실제 결과나 신뢰할 수 있는 자료를 통해 확인하는 과정이다.

이번 학습에서는 이 세 가지가 서로 연결되어 있다는 점을 배웠다.

좋은 질문을 작성하는 것도 중요하지만, 충분한 정보를 제공하고 결과를 검증하는 과정까지 이어져야 AI를 효과적으로 활용할 수 있다.

## 7. 최종 확인 문제

Day 1 학습 내용을 확인하기 위해 다음 문제를 풀었다.

**문제:**

AI가 Unity 공격 애니메이션 문제에 대한 코드를 작성해 주었다. 코드를 살펴보면 논리적으로 문제가 없어 보이지만 실제 Unity에서는 애니메이션이 여전히 재생되지 않는다.

이때 가장 적절한 다음 행동은 무엇일까?

- A. AI에게 전체 코드를 다시 작성해 달라고 요청한다.
- B. 실제 실행 상태와 Animator 설정을 확인하고 예상 동작과 비교한다.
- C. 같은 코드를 다른 AI 모델에 입력한다.
- D. AI가 작성한 코드가 논리적으로 맞으므로 Unity 설정을 변경한다.

**정답: B**

AI가 제공받지 못한 정보가 실제 실행 환경에 있을 수 있기 때문이다.

코드만으로 원인을 확정하기보다 실제 실행 결과와 Animator 설정 등을 확인하고, 그 정보를 바탕으로 문제를 다시 분석하는 것이 적절하다고 판단했다.

## 8. 오늘의 회고

오늘은 AI를 활용하는 데 있어 질문을 작성하는 방식 자체가 중요하다는 점을 공부했다.

단순히 질문을 입력하는 것보다 원하는 작업과 배경, 조건, 결과 형태를 명확히 전달하는 것이 중요하다.

특히 Python List와 Tuple 비교 실습을 통해 기존에 알고 있던 C# 지식을 AI에게 전달하면 새로운 개념을 이해하는 데 도움이 된다는 점을 확인했다.

Unity 애니메이션 오류 분석 실습에서는 내가 생각한 원인을 AI에게 전달하더라도 그것을 정답으로 가정하지 않도록 요청하는 것이 중요하다는 점을 배웠다.

또한 AI가 제공한 답변이 논리적으로 타당해 보이더라도 실제 실행 결과와 다를 수 있다. AI가 알지 못하는 정보가 무엇인지 파악하고, 필요한 정보를 직접 확인하는 과정이 중요하다.

앞으로는 AI를 단순한 정보 검색 도구로 사용하는 것을 넘어, 문제 해결과 개발 과정에서 효과적으로 활용하는 방법을 익히고 싶다.

### 앞으로 적용할 AI 활용 원칙

1. 원하는 작업을 명확하게 전달한다.
2. AI가 문제를 이해하는 데 필요한 배경 정보를 제공한다.
3. 결과물의 조건과 형태를 구체적으로 요청한다.
4. AI의 답변을 정답으로 가정하지 않는다.
5. 실제 결과를 확인하고 필요한 경우 다시 질문한다.
